# Crakbit Chain v0.36 Alpha — Controlled Public-Testnet Integration

**Package:** `0.36.0a1`  
**Active devnet PoW:** `crakpow-scrypt-v1`  
**RandomX:** optional candidate only; not active consensus  
**P2P:** `crakbit-p2p/1`  
**Pool:** `crakbit-pool/2`  
**Status:** controlled public-testnet integration tooling — **not production mainnet**.

Production CRKBIT has not launched. There is no official presale or production token contract.

## Purpose

v0.36 turns the v0.35 evidence formats into a more usable real campaign workflow without fabricating elapsed time or silently changing consensus.

## Implemented

- append-only signed/hash-chained multi-node campaign log,
- live probing of multiple `/pow/v2` nodes per sample,
- real elapsed-time 24h/72h/7d campaign summary gates,
- sample-level convergence and availability ratios,
- resumable long-running collector script,
- peer-book seed selection integrated into a v0.36 node wrapper,
- coarse peer-bucket diversity applied at startup,
- disposable incremental UTXO undo rehearsal,
- clean-replay comparison of incremental rollback results,
- explicit RandomX/scrypt testnet activation proposal format,
- minimum activation notice window,
- activation proposal requires a prior human algorithm decision,
- RandomX proposal binds consensus-vector and native-library SHA-256 values,
- proposal never claims that consensus is already activated,
- independent-review handoff artifact combining v0.35 freeze, 7-day campaign evidence, undo rehearsal and optional activation proposal,
- software-enforced `production_mainnet_ready=false`.

## Real-time campaign collector

One sample can be collected with:

```powershell
crakchain pow-campaign-v36-probe `
  --key private\campaign-evidence.json `
  --log evidence\campaign-v36.jsonl `
  --rpc-url https://node-a.example `
  --rpc-url https://node-b.example `
  --rpc-url https://node-c.example `
  --rpc-url https://node-d.example
```

For a continuous campaign:

```powershell
python scripts\run_pow_campaign_v36.py `
  --key private\campaign-evidence.json `
  --log evidence\campaign-v36.jsonl `
  --rpc-url https://node-a.example `
  --rpc-url https://node-b.example `
  --rpc-url https://node-c.example `
  --rpc-url https://node-d.example `
  --interval-seconds 60 `
  --duration-seconds 86400
```

The collector writes local real-time timestamps. The CLI does not accept caller-supplied sample timestamps, so a short run cannot be turned into a fake 24h/72h/7d campaign by CLI arguments.

Verify and summarize:

```powershell
crakchain pow-campaign-v36-verify --log evidence\campaign-v36.jsonl

crakchain pow-campaign-v36-summarize `
  --log evidence\campaign-v36.jsonl `
  --required-level 24h `
  --minimum-nodes 4 `
  --minimum-sample-success-ratio 0.99 `
  --output evidence\campaign-summary-v36.json
```

A review handoff requires a real 7-day summary, not only 24h evidence.

## Peer-book node startup integration

v0.34 introduced a persistent peer book. v0.36 can now use that book when starting a node:

```powershell
crakchain pow-node-v36-run `
  --db runtime\node1\chain.sqlite3 `
  --network-key private\node1-p2p.json `
  --peer-db runtime\node1\peers.sqlite3 `
  --rpc-host 127.0.0.1 `
  --rpc-port 28443 `
  --p2p-port 28444 `
  --max-per-bucket 2
```

Inspect selected seeds separately:

```powershell
crakchain pow-peer-seeds-v36-select `
  --peer-db runtime\node1\peers.sqlite3 `
  --limit 16 `
  --max-per-bucket 2
```

The diversity buckets are only a coarse IP/DNS concentration defense. They do not prove provider, ASN or operator independence.

## Incremental undo rehearsal

v0.34 created UTXO undo metadata. v0.36 now actually applies those records on a disposable copy and compares the result against a clean replay to the same height:

```powershell
crakchain pow-undo-v36-rehearse `
  --db runtime\node1\chain.sqlite3 `
  --disconnect-blocks 5 `
  --output evidence\undo-rehearsal-v36.json
```

The source database is never modified by this rehearsal.

This does **not** switch the live v0.32 canonical reorg engine to incremental undo yet. That remains a separate consensus-critical change requiring deeper review.

## Algorithm activation proposal

v0.36 deliberately separates algorithm choice from consensus activation.

If real benchmark evidence later results in a human `randomx` decision, an activation proposal can be built:

```powershell
crakchain pow-activation-v36-build `
  --key private\release-evidence.json `
  --algorithm-decision evidence\algorithm-decision.json `
  --source-commit <40-char-git-sha> `
  --chain-id crakbit-pow-testnet-v1 `
  --genesis-hash <64-hex-genesis> `
  --current-height 10000 `
  --activation-height 12000 `
  --consensus-vectors-sha256 <64-hex> `
  --randomx-library-sha256 <64-hex> `
  --minimum-notice-blocks 1000 `
  --output evidence\activation-proposal-v36.json
```

The artifact always records:

```text
consensus_activated=false
production_mainnet_ready=false
```

A separate versioned node release and multi-node fork/reorg campaign are required before any actual RandomX testnet activation.

## Independent-review handoff

After a valid v0.35 freeze, a real 7-day v0.36 campaign and a passing undo rehearsal:

```powershell
crakchain pow-handoff-v36-build `
  --key private\release-evidence.json `
  --source-commit <exact-v0.36-sha> `
  --chain-id crakbit-pow-testnet-v1 `
  --genesis-hash <64-hex-genesis> `
  --v35-freeze evidence\public-testnet-freeze-v35.json `
  --campaign-summary evidence\campaign-summary-7d-v36.json `
  --undo-rehearsal evidence\undo-rehearsal-v36.json `
  --output evidence\independent-review-handoff-v36.json
```

An optional activation proposal may also be bound into the handoff.

The handoff means evidence is ready to send to reviewers. It does **not** mean an independent review is complete.
