# Crakbit Chain v0.31 Alpha — Native Proof-of-Work Pivot

**Package:** `0.31.0a1`  
**New consensus research path:** native Proof of Work  
**Working v0.31 PoW:** `crakpow-scrypt-v1`  
**Ledger:** Bitcoin-style UTXO model  
**Status:** CPU-mineable devnet alpha — **not production mainnet**.

Production CRKBIT has **not launched**. There is no official CRKBIT presale or production token contract. The v0.31 parameters are research/devnet parameters and must not be represented as final production monetary policy.

## Why v0.31 is a major architecture change

The previous chain research path used CometBFT validators to order/finalize blocks. The project direction now targets a Bitcoin-like mining model where miners perform computational work and valid blocks extend a proof-of-work chain.

The CometBFT implementation is retained in the repository as legacy/research infrastructure so prior security, release, monitoring and evidence work is not destroyed. It is **not** silently mixed with the new PoW consensus path.

## What is implemented now

v0.31 adds a separate native PoW devnet engine with:

- deterministic genesis configuration,
- Ed25519 `crk1...` ownership keys reused from the existing wallet primitives,
- Bitcoin-style unspent transaction outputs (UTXOs),
- signed multi-input / multi-output transfers,
- transaction fees,
- mempool admission with double-spend prevention,
- coinbase transactions,
- configurable block subsidy and halving interval,
- coinbase maturity,
- Merkle roots over transaction IDs,
- memory-hard `hashlib.scrypt` proof-of-work hashing,
- explicit 256-bit target validation,
- automatic bounded difficulty retargeting,
- cumulative chain-work accounting,
- CPU solo-mining loop,
- SQLite-backed chain/UTXO/mempool state,
- HTTP node RPC for templates, blocks, transactions, balances and UTXOs,
- first-party mining-pool accounting,
- easier pool share targets separated from network difficulty,
- test PPLNS internal balance accounting,
- a native JSON-line pool protocol,
- a native CPU pool-miner script,
- regression tests for mined blocks, maturity, transfers, fees, double-spend policy and pool accounting.

## Important algorithm decision

The long-term CPU-first target can still be evaluated against RandomX, but v0.31 does **not** pretend that a RandomX integration exists before it has been implemented and benchmarked.

`crakpow-scrypt-v1` is used in this alpha because Python provides a real memory-hard scrypt primitive with no unverified external native dependency. It lets the project test actual proof-of-work blocks, targets, coinbase rewards, mining and pool behavior now.

Before any production launch the project should benchmark and independently review:

1. the v0.31 scrypt design,
2. a real RandomX native-library integration,
3. CPU/GPU/ASIC economics,
4. denial-of-service cost at block-validation boundaries,
5. seed/key scheduling,
6. miner interoperability.

The production PoW algorithm is therefore **not frozen**.

## Node RPC

Run a local node:

```bash
crakchain pow-node-v31-run \
  --db runtime/pow-v31/chain.sqlite3 \
  --host 127.0.0.1 \
  --port 28443
```

Read-only / mining endpoints:

```text
GET  /pow/v1/health
GET  /pow/v1/info
GET  /pow/v1/block/{height}
GET  /pow/v1/balance/{address}
GET  /pow/v1/utxos/{address}
GET  /pow/v1/mempool
POST /pow/v1/getblocktemplate
POST /pow/v1/submitblock
POST /pow/v1/submittransaction
```

The service should remain private or access-controlled while the protocol is alpha.

## Solo CPU mining

Create a wallet and devnet database:

```bash
crakchain pow-wallet-v31-new --output private/miner.json

crakchain pow-chain-v31-init \
  --db runtime/pow-v31/chain.sqlite3 \
  --chain-id crakbit-pow-devnet-v1
```

Then mine to the public `crk1...` address from that wallet:

```bash
crakchain pow-mine-v31 \
  --db runtime/pow-v31/chain.sqlite3 \
  --miner-address crk1YOUR_ADDRESS \
  --blocks 1
```

A valid block must satisfy the network target. The node verifies the Merkle root, timestamp, target, deterministic PoW seed, scrypt proof, transaction signatures, UTXO conservation, coinbase reward and maturity rules before committing it.

## Native mining pool

Run the PoW node first, then start the first-party pool:

```bash
crakchain pow-pool-v31-run \
  --db runtime/pow-v31/pool.sqlite3 \
  --node-url http://127.0.0.1:28443 \
  --pool-address crk1POOL_PAYOUT_ADDRESS \
  --host 127.0.0.1 \
  --port 3333
```

Run the native pool miner:

```bash
python scripts/run_pow_pool_miner_v31.py \
  --host 127.0.0.1 \
  --port 3333 \
  --address crk1MINER_PAYOUT_ADDRESS \
  --worker cpu-01
```

### Pool boundary

The v0.31 pool protocol is `crakbit-pool/1`, a project-native JSON-line mining protocol used to validate pool jobs, share targets, block submissions and accounting.

It is **not yet XMRig/RandomX Stratum compatible**. A future compatibility layer must be implemented against the final PoW algorithm/job format rather than falsely advertising compatibility now.

PPLNS balances in v0.31 are internal test accounting. Automatic on-chain pool payouts are deliberately not enabled yet.

## Current chain-selection boundary

v0.31 tracks cumulative work but its SQLite node accepts only blocks extending the current canonical tip. Full peer networking, competing fork storage and highest-cumulative-work reorganization are **not yet implemented**.

That means v0.31 is a real CPU-mineable PoW blockchain **devnet prototype**, but it is not yet a decentralized Bitcoin-like production network.

## Required next PoW phase

The next major PoW work should add:

- peer-to-peer node discovery and authenticated message framing,
- block/transaction gossip,
- header-first synchronization,
- side-chain storage,
- highest-cumulative-work fork choice and safe UTXO reorganization/undo data,
- orphan handling,
- median-time-past style timestamp rules,
- stronger mempool policy and fee selection,
- multi-process/native optimized miner integration,
- RandomX adapter + benchmark/review if selected,
- Stratum compatibility for the final mining algorithm,
- variable difficulty and stronger pool anti-abuse controls,
- mature PPLNS payout transaction construction,
- explorer integration for PoW difficulty/hashrate/coinbase/miner data,
- long-lived multi-node public PoW testnet.

## Monetary-policy boundary

The default devnet subsidy/halving values are test parameters. The previously discussed `21,000,000 CRKBIT` and `8 decimals` remain proposals unless intentionally finalized after technical, economic-security and legal/regulatory review.

## Security boundary

- Do not commit wallet/miner/pool private keys.
- Do not expose a hot pool payout key through the public pool server.
- Keep node administration/RPC mutation surfaces private or authenticated.
- Do not use v0.31 for real-value custody.
- Do not describe devnet pool balances as investment returns.
- Do not claim production mainnet or production CRKBIT launch from this alpha.
