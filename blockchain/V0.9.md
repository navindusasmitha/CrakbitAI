# Crakbit Chain v0.9 Alpha — Integrity, Verified Backups & Observability

**Status:** research/devnet alpha. Not production-ready and not suitable for custody of real value.

v0.9 focuses on operator safety: detecting local database/history damage, creating verifiable online backups and making validator behavior easier to observe during longer-running devnet experiments.

This phase deliberately does **not** claim that the unresolved consensus and transport blockers are solved. The conservative cross-round lock and reviewed mutually authenticated validator transport remain open work.

## What v0.9 Adds

### `crakchain doctor`

A new local integrity checker validates the node database without trusting the public RPC surface.

Quick mode:

```bash
crakchain doctor \
  --genesis runtime/genesis.json \
  --data runtime/node1-data
```

Full mode:

```bash
crakchain doctor \
  --genesis runtime/genesis.json \
  --data runtime/node1-data \
  --full
```

Quick checks include:

- SQLite `PRAGMA quick_check`,
- configured genesis fingerprint,
- chain-tip metadata,
- issued-supply conservation,
- snapshot-base metadata consistency.

Full mode additionally verifies all **locally stored** history:

- contiguous local block heights,
- previous-hash continuity,
- reconstructed block hashes,
- proposer schedule and Ed25519 signatures,
- transaction Merkle roots,
- view-change certificates,
- prevote certificates,
- precommit certificates,
- local transaction index consistency.

For snapshot-bootstrapped nodes, the checker starts at the certified snapshot base and does not pretend that pre-snapshot history is locally present.

### Integrity RPC

Development operator endpoints:

```text
GET /integrity/status
GET /integrity/status?full=true
GET /operations/status
```

The default integrity endpoint runs the quick checks. Full history verification is opt-in because it can be more expensive on a larger local chain.

### Verified online SQLite backups

The CLI can create a consistent SQLite backup using SQLite's online backup API:

```bash
crakchain backup-create \
  --genesis runtime/genesis.json \
  --data runtime/node1-data \
  --output runtime/backups/node1.sqlite3
```

Before publishing the backup, the copied database must pass the full v0.9 integrity check.

A sidecar manifest is written as:

```text
node1.sqlite3.manifest.json
```

The manifest records:

- format version,
- chain ID,
- genesis fingerprint,
- finalized height,
- last block hash,
- snapshot base height when applicable,
- backup byte size,
- SHA-256 of the complete SQLite file,
- creation timestamp.

Verify later with:

```bash
crakchain backup-verify \
  --genesis runtime/genesis.json \
  --backup runtime/backups/node1.sqlite3 \
  --manifest runtime/backups/node1.sqlite3.manifest.json \
  --full
```

Verification rejects a mismatched file size, SHA-256, chain identity, genesis fingerprint, height/tip metadata or failed database integrity check.

### Prometheus + Grafana development stack

`blockchain/ops/` now includes:

- Prometheus scrape configuration for the four local validator RPC ports,
- a Docker Compose development observability stack,
- a provisioned Grafana Prometheus datasource,
- a basic validator dashboard.

Start the blockchain first, then:

```bash
cd blockchain/ops
docker compose -f docker-compose.observability.yml up -d
```

Development endpoints:

```text
Prometheus: http://127.0.0.1:9090
Grafana:    http://127.0.0.1:3000
```

The included Grafana credentials are development defaults and must never be exposed unchanged on a public host.

## What v0.9 Does Not Claim

v0.9 does **not** solve the major mainnet blockers.

Still outstanding:

- mature proof-based cross-round BFT lock/unlock semantics or migration to a reviewed BFT core,
- formal safety/liveness analysis,
- mutually authenticated encrypted validator transport,
- certificate pinning/rotation lifecycle,
- production validator key management,
- archive/history synchronization for snapshot-bootstrapped nodes,
- adversarial partition/latency/Byzantine/load testing at meaningful duration,
- production RPC abuse controls,
- production alert routing/log aggregation/SLOs,
- independent consensus/network/security audit.

The current chain remains a research devnet and must not custody real value.

## Recovery / Operations Model

v0.7 and v0.8 added quorum-certified snapshots, resumable chunk transfer and crash-visible snapshot import journaling. v0.9 adds a second operational layer around that recovery path:

```text
quorum-certified snapshot
        ↓
verified import / resumable transfer
        ↓
local integrity checks
        ↓
verified online backup
        ↓
Prometheus / Grafana operator visibility
```

These tools improve failure diagnosis and recovery practice, but they do not change the consensus trust assumption.

## Next Engineering Phase — v0.10

Priorities for the next phase:

1. Resolve the conservative cross-round consensus lock through a reviewed proof-based BFT design or migration to an established BFT core.
2. Add mutually authenticated encrypted validator transport and certificate/key lifecycle management.
3. Add archive/history synchronization for snapshot-bootstrapped nodes.
4. Add bounded RPC/mempool/request abuse controls.
5. Build repeatable partition, latency, Byzantine and load-test harnesses.
6. Add backup restore drills and abrupt-power-loss/database-corruption test automation.
7. Add alert rules, authenticated monitoring and incident-response runbooks.
8. Prepare reproducible public-testnet deployment manifests.
9. Improve faucet, wallet and explorer testnet UX.
10. Commission external consensus/network review before any public-value use.
