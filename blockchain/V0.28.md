# Crakbit Chain v0.28 Alpha — Launch Rehearsal / Corroborated Evidence

**Package:** `0.28.0a1`  
**Consensus candidate:** CometBFT `v0.40.0`  
**Governed execution:** `crakbit-execution/3`  
**Status:** launch-rehearsal / independently-corroborated-evidence tooling — **not production mainnet**.

Production CRKBIT has **not launched**. There is no official CRKBIT presale or production token contract. v0.28 deliberately does not contain a command that automatically starts a production mainnet, changes production DNS, moves funds or turns test CRKBIT into a production-value asset.

## Purpose

v0.27 defined a final mainnet-candidate policy/evidence gate. v0.28 moves the software boundary one step closer to real operations by defining how a team can rehearse genesis/cutover/rollback, measure redundant public edges, drill protected signer recovery, rehearse coordinated upgrades, maintain a final risk register, collect independent technical reviewer sign-offs, import external reproducible-build evidence and freeze an exact release candidate for a **manual human launch/no-launch review**.

The tooling can verify cryptographic signatures and internal consistency of supplied evidence. It cannot prove that a VPS, HSM, reviewer, outage drill or provider control existed in the real world unless the underlying evidence is independently corroborated.

## What v0.28 adds

- package/CLI `0.28.0a1`,
- signed launch-rehearsal runbook with 4+ validator start order, genesis steps and rollback steps,
- explicit dry-run/no-automatic-network-mutation boundary,
- signed DNS/RPC/explorer cutover rehearsal that requires rollback + redundant failover checks,
- configurable public-edge SLO/capacity/failover evidence,
- protected HSM/remote-signer rotation + catastrophic-recovery drill evidence,
- coordinated upgrade + rollback rehearsal bound to the signed v0.27 upgrade plan,
- final signed unresolved-risk register with hard blockers for unmitigated high/critical risks,
- independent technical reviewer sign-offs bound to the exact v0.27 final report,
- required technical scopes: consensus/application, network/RPC, cryptography/key-management and browser wallet,
- external reproducible-build/transitive-dependency attestation bound to exact source/candidate identity,
- aggregate v0.28 launch-rehearsal gate,
- signed final release-candidate freeze only after the rehearsal gate passes,
- signed manual decision record (`hold` or `approve-launch-window`) that still performs no automatic launch,
- explicit `production_mainnet_ready=false`, `production_mainnet_launched=false` and `production_crkbit_launched=false` throughout.

## Launch runbook

The runbook requires at least four unique validator IDs, an exact validator start order, genesis-ceremony steps, rollback steps and a cutover window of at least 15 minutes.

It always records:

```text
dry_run_only=true
automatic_network_mutation=false
automatic_dns_change=false
automatic_fund_movement=false
production_mainnet_ready=false
```

This is intentional. A runbook is evidence/planning, not a production-launch engine.

## Cutover rehearsal

The cutover rehearsal requires:

- at least one intended DNS name,
- at least two RPC endpoints,
- at least two explorer endpoints,
- a declared DNS TTL,
- verified rollback,
- RPC failover verification,
- explorer failover verification,
- an explicit assertion that production DNS was not changed during the rehearsal.

## Public-edge SLO evidence

v0.28 does not invent a universal latency/capacity target. The operator/reviewer supplies explicit thresholds and measured values for:

- availability,
- p95 latency,
- error rate,
- capacity in requests/second,
- sustained test duration,
- failover time.

The signed record states whether the supplied measurements satisfy the supplied thresholds. This still needs independent corroboration before it can be treated as real launch evidence.

## Protected signer recovery drill

The signer drill supports `hsm`, `remote-signer`, `hardware-backed` or an equivalent protected custody path. A passing drill requires:

- no private-key export,
- successful rotation,
- old-key revocation,
- successful backup recovery,
- catastrophic-recovery rehearsal,
- validator quorum preserved during the drill.

No private key is embedded in the evidence artifact.

## Upgrade / rollback rehearsal

The v0.28 upgrade rehearsal verifies the signed v0.27 upgrade plan and then records whether a strict >2/3 validator set successfully completed the rehearsal, converged to the same application hash, exercised rollback, reconverged and preserved data.

The artifact does not automatically upgrade a network.

## Final risk register

Each risk has a stable operator-provided ID, severity, status, owner and description. Accepted risks require a rationale. A high or critical risk blocks the v0.28 rehearsal gate unless it is marked `mitigated`.

`risk_gate_satisfied=true` is therefore stricter than merely documenting a high/critical risk acceptance.

## Independent technical reviewer sign-offs

Each reviewer sign-off is separately signed and bound to:

- exact candidate source commit,
- exact candidate identity SHA-256,
- exact signed v0.27 final-report manifest SHA-256,
- one review scope,
- decision (`passed`, `conditional` or `failed`).

The aggregate gate requires passed/independent sign-offs covering:

- `consensus-application`,
- `network-rpc`,
- `cryptography-key-management`,
- `browser-wallet`,

and at least three unique review signers by default. v0.27 separately covers economic-security and legal/regulatory attestations.

A signature proves which key signed a statement. It does not itself prove a reviewer is actually independent.

## External reproducible-build evidence

The external reproducibility record binds:

- exact source commit,
- exact candidate identity,
- package version,
- dependency-lock hash,
- SBOM hash,
- Python wheel hash,
- Go bridge binary hash,
- reproducible Python/Go assertions,
- transitive dependency review,
- source-tag verification.

## v0.28 rehearsal gate

The aggregate gate requires:

- a valid v0.27 final report with `mainnet_candidate_gate_satisfied=true`,
- exact candidate identity across every v0.28 artifact,
- passing launch runbook,
- passing cutover rehearsal,
- at least two unique passing public-edge SLO records,
- passing protected-signer recovery drill,
- passing coordinated upgrade/rollback rehearsal,
- no unmitigated high/critical final risks,
- passing external reproducible-build attestation,
- exact-v0.27-report reviewer binding,
- all four required technical review scopes passed,
- at least three unique review signers.

Even if every check is true, the result is only:

```text
launch_rehearsal_gate_satisfied=true
manual_launch_decision_required=true
automatic_launch=false
production_mainnet_ready=false
production_mainnet_launched=false
production_crkbit_launched=false
```

## Final release freeze and manual decision

`release-freeze-v28-build` can freeze an exact candidate only after the rehearsal gate passes. It binds the rehearsal gate and optional evidence artifacts by SHA-256.

`launch-decision-v28-record` supports only:

- `hold`, or
- `approve-launch-window`.

Even `approve-launch-window` is a signed human-decision record only. It does not change DNS, start validators, move funds or mark production mainnet as launched.

## Real work still required

The repository does not prove that the following happened merely because v0.28 tooling exists:

- four or more independently managed validators actually ran continuously,
- a genuine multi-operator genesis ceremony occurred,
- a genuine seven-day or longer soak completed,
- real fault/load/state-sync/governance campaigns passed,
- protected HSM/remote-signer custody was really deployed and recovered,
- the measured public-edge SLOs came from real production-style infrastructure,
- the review signers are genuinely independent experts,
- a complete independent security review was completed,
- final economics and legal conclusions are suitable for a production-value launch.

Those are external operational/review tasks. Production launch remains a separate explicit human decision after real evidence is reviewed.
