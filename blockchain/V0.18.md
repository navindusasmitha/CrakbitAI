# Crakbit Chain v0.18 Alpha — Review Freeze, Explorer Reconciliation & Soak Evidence

**Status:** public-testnet / mainnet-candidate review infrastructure alpha. **Not a production mainnet and not suitable for custody of real value.**

v0.18 intentionally reduces feature expansion and focuses on making a candidate easier to reproduce, reconcile, freeze and hand to independent reviewers. Production CRKBIT has **not** launched. There is no official CRKBIT presale or production token contract.

## 1. Signed review-candidate freeze

New module:

```text
crakbit_chain/review_freeze.py
```

New CLI commands:

```text
crakchain review-freeze-build
crakchain review-freeze-verify
```

A review-freeze manifest binds:

- exact Git source commit,
- Crakbit package version,
- declared CometBFT version,
- chain ID and genesis fingerprint,
- exact genesis-file SHA-256,
- operator-selected review artifacts and their SHA-256 hashes,
- a dedicated Ed25519 review signer.

Typical artifacts can include the signed release manifest, signed evidence bundle, genesis ceremony artifact, explorer reconciliation output, soak evidence, fault-campaign output and recovery evidence.

The freeze format deliberately records:

```text
candidate_frozen_for_review = true
independent_review_completed = false
production_mainnet_ready = false
production_crkbit_launched = false
```

A review-freeze is therefore a reproducibility/integrity artifact, not an audit certificate.

Example:

```bash
crakchain review-freeze-build \
  --genesis runtime/genesis.json \
  --key private/review-signing-key.json \
  --source-commit EXACT_GIT_COMMIT \
  --package-version 0.18.0a1 \
  --cometbft-version v0.40.0 \
  --artifact evidence=runtime/evidence/public-testnet-evidence.json \
  --artifact reconcile=runtime/evidence/explorer-reconcile.json \
  --artifact soak=runtime/evidence/soak.json \
  --output runtime/review/crakbit-v0.18-review-freeze.json
```

Never commit the review-signing private key.

## 2. Clean explorer reconciliation

New module:

```text
crakbit_chain/explorer_reconcile.py
```

New command:

```text
crakchain explorer-reconcile
```

The reconciler builds a brand-new explorer index from the external application database and compares it with the deployed/current index using deterministic per-table SHA-256 fingerprints for:

- commits,
- transactions,
- address activity,
- account state.

It also compares indexed height, snapshot-base height, source last hash and issued-supply totals. This makes explorer divergence visible without mutating the current index.

Example:

```bash
crakchain explorer-reconcile \
  --genesis runtime/genesis.json \
  --source-data runtime/comet-app \
  --index runtime/explorer-index.sqlite3 \
  --rebuilt-output runtime/reconcile/explorer-clean.sqlite3 \
  --output runtime/evidence/explorer-reconcile.json
```

The command exits non-zero when the existing index does not match a clean rebuild.

## 3. Sustained health / soak evidence

New:

```text
crakbit_chain/soak_evidence.py
scripts/run_testnet_soak.py
```

The soak collector repeatedly samples the v0.16+ multi-host health inventory and records the raw health snapshots plus a deterministic summary:

- sample count,
- healthy/unhealthy sample count,
- maximum observed validator height spread,
- whether every sample was healthy.

Example:

```bash
python scripts/run_testnet_soak.py \
  --inventory private/testnet-inventory.json \
  --duration-seconds 21600 \
  --interval-seconds 30 \
  --max-height-spread 2 \
  --output runtime/evidence/soak-6h.json
```

The result only records endpoints actually sampled by the operator. It does **not** infer that endpoints are independently owned/hosted merely from URLs, hostnames or provider labels.

## 4. v0.17 state sync remains the recovery base

v0.18 retains the v0.17 CometBFT ABCI snapshot lifecycle:

```text
ListSnapshots
OfferSnapshot
LoadSnapshotChunk
ApplySnapshotChunk
```

Snapshot acceptance remains bound to the CometBFT-supplied trusted application hash, with per-chunk and whole-artifact SHA-256 verification and restore restricted to pristine application state.

v0.18 does not claim live independent-host recovery evidence unless operators actually perform and publish it.

## 5. Review-candidate workflow

Recommended evidence order:

1. pin exact source commit and CometBFT version,
2. perform multi-host health/soak collection,
3. run controlled failure/recovery campaigns,
4. demonstrate clean-host state sync,
5. reconcile explorer state against a clean rebuild,
6. create/verify signed release and genesis/evidence artifacts,
7. build the signed v0.18 review-freeze manifest,
8. give the frozen source/artifacts to independent reviewers,
9. remediate findings and freeze a new candidate if code changes.

Any source-code change after a freeze means the old freeze no longer describes the current candidate.

## 6. Tests / CI

v0.18 adds tests for:

- review-freeze signature verification,
- source/genesis/artifact binding,
- tamper rejection,
- explorer clean-rebuild reconciliation,
- conservative soak summaries.

The existing workflow continues to run the Python suite and the CometBFT Go bridge suite.

## External gates still open

v0.18 cannot complete tasks that require independent infrastructure, operators or auditors by repository changes alone. The following remain open until actually performed and documented:

1. long-lived 4-validator operation across independently managed hosts/providers,
2. live clean-host CometBFT state-sync recovery with app-hash convergence,
3. real partition/packet-loss/latency/process-kill/sustained-load campaigns,
4. deployed and drilled remote-signer/HSM-equivalent validator custody,
5. multi-operator genesis ceremony with independently held keys,
6. independent consensus/application/network/browser-wallet review,
7. production multi-edge WAF/DDoS/capacity architecture,
8. finalized validator incentives/economics and applicable legal/regulatory review.

## Suggested next phase — v0.19

v0.19 should start only after real external evidence exists. Its focus should be remediation and release engineering:

- ingest independent-review findings,
- fix and regression-test verified findings,
- reproducible binary/container builds,
- SBOM/dependency pinning and release provenance,
- upgrade/migration rehearsals,
- validator-set lifecycle drills,
- incident-response runbooks and restore exercises,
- a second signed review freeze after remediation.

Until the external gates are satisfied, use **public testnet**, **research network**, **review candidate** or **mainnet-candidate infrastructure** — not production mainnet.
