# Crakbit Chain v0.25 Alpha — Independent-Host Evidence / Review Freeze

**Package:** `0.25.0a1`  
**Consensus candidate:** CometBFT `v0.40.0`  
**Governed execution:** `crakbit-execution/3`  
**Status:** public-testnet / independent-review-candidate tooling — **not production mainnet**.

Production CRKBIT has **not launched**. There is no official CRKBIT presale or production token contract. Testnet units have no production-value claim and this software must not be used to custody real value.

## Purpose

v0.24 added operational preflight, fault/recovery records, redundancy checks, protected-signer records and explicit 24h/72h/7-day gates. v0.25 adds the evidence boundary required before an exact source/artifact set can be frozen and handed to independent reviewers.

The important distinction is that v0.25 can validate **signed operator evidence and consistency**, but it cannot independently prove that a claimed VPS, provider, region, soak duration or drill actually existed. Host records are explicitly marked `operator_self_attested=true` and `independently_verified=false`.

## What v0.25 adds

- package/CLI `0.25.0a1`,
- normalized alert/incident-response records,
- monotonic acknowledgement/resolution timing checks,
- escalation requirement for high/critical incidents,
- recovery-verification gate before an incident is considered closed,
- signed per-operator host attestations using a dedicated evidence-signing key,
- exact source commit / package / CometBFT / application-genesis / consensus-genesis binding,
- required 7-day soak, backup/restore, clean-host state sync, governance-campaign and protected-signer assertions,
- required restart/process-kill/partition/latency/packet-loss/load/storage campaign coverage,
- four-or-more unique operator / validator / signer gate,
- provider and region diversity gates,
- single-source/single-genesis consistency gate,
- v0.24 operational-readiness dependency,
- incident-response drill dependency,
- signed review-freeze manifest tied to exact genesis files, review gate and review artifacts,
- explicit independent-review scope list,
- hard-coded claims that independent review is not yet completed and production mainnet is not ready,
- v0.25 regression tests.

## 1. Incident-response evidence

After an **authorized** operational drill or real incident, record the timeline and recovery state:

```bash
crakchain incident-v25-record \
  --incident-id drill-rpc-failover-001 \
  --severity high \
  --started-at-ms 1789584000000 \
  --acknowledged-at-ms 1789584030000 \
  --resolved-at-ms 1789584300000 \
  --alert-source alertmanager \
  --component public-rpc \
  --component explorer \
  --escalation-target on-call-operator \
  --summary "Authorized public edge failover drill" \
  --recovery-verified \
  --output runtime/evidence/incident-rpc-failover.json
```

High and critical incidents cannot be recorded without an escalation target. A record is only `closed=true` when it has a valid resolution time and recovery has been verified.

## 2. Independent-host operator attestation

Each operator should use a **dedicated evidence-signing key**, separate from the validator consensus key, wallet key and release key.

```bash
crakchain host-attestation-v25-build \
  --key /etc/crakbit/evidence-key.json \
  --operator-id operator-1 \
  --validator-id validator-1 \
  --provider provider-a \
  --region region-a \
  --node-id COMET_NODE_ID \
  --source-commit EXACT_GIT_SHA \
  --application-genesis-sha256 APP_GENESIS_SHA256 \
  --consensus-genesis-sha256 COMET_GENESIS_SHA256 \
  --independent-management-asserted \
  --protected-signer-drilled \
  --soak-7d-completed \
  --backup-restore-drilled \
  --clean-host-state-sync-drilled \
  --governance-campaign-completed \
  --fault-kind restart \
  --fault-kind process-kill \
  --fault-kind partition \
  --fault-kind latency \
  --fault-kind packet-loss \
  --fault-kind load \
  --fault-kind storage \
  --output runtime/evidence/validator-1-attestation.json
```

The resulting envelope is cryptographically signed, but it remains an **operator self-attestation**, not independent validation of the real-world claims.

Verify it:

```bash
crakchain host-attestation-v25-verify \
  --attestation runtime/evidence/validator-1-attestation.json
```

## 3. Review gate

A review freeze cannot be built unless the v0.25 gate is satisfied. The gate requires:

- a successful v0.24 operational-review-candidate record,
- at least four signed host attestations,
- unique operator IDs,
- unique validator IDs,
- unique operator evidence signers,
- at least two providers,
- at least two regions,
- every host gate satisfied,
- one exact source commit,
- one package version,
- one CometBFT version,
- one application genesis hash,
- one consensus genesis hash,
- at least one incident-response drill record,
- every incident closed with recovery verified.

Example:

```bash
crakchain review-gate-v25-build \
  --operational-readiness runtime/evidence/readiness-v24.json \
  --host-attestation runtime/evidence/validator-1-attestation.json \
  --host-attestation runtime/evidence/validator-2-attestation.json \
  --host-attestation runtime/evidence/validator-3-attestation.json \
  --host-attestation runtime/evidence/validator-4-attestation.json \
  --incident runtime/evidence/incident-rpc-failover.json \
  --output runtime/evidence/review-gate-v25.json
```

## 4. Freeze exact review candidate

Only after `candidate_freeze_allowed=true`:

```bash
crakchain review-freeze-v25-build \
  --key runtime/review-freeze-key.json \
  --source-commit EXACT_GIT_SHA \
  --application-genesis runtime/application-genesis.json \
  --consensus-genesis runtime/cometbft-genesis.json \
  --review-gate runtime/evidence/review-gate-v25.json \
  --artifact operational-readiness=runtime/evidence/readiness-v24.json \
  --artifact review-gate=runtime/evidence/review-gate-v25.json \
  --artifact soak-summary=runtime/evidence/soak-7d-summary.json \
  --review-scope "consensus/application" \
  --review-scope "validator governance" \
  --review-scope "network/RPC" \
  --review-scope "cryptography/key custody" \
  --review-scope "browser wallet" \
  --output runtime/review-freeze-v25.json
```

The freeze binds:

- exact source commit,
- package and CometBFT version,
- application genesis hash,
- consensus genesis hash,
- the exact review-gate hash,
- each named review artifact by SHA-256,
- explicit reviewer scope,
- the evidence signer identity.

It deliberately records:

- `independent_security_review_completed=false`,
- `production_mainnet_ready=false`,
- `production_crkbit_launched=false`.

## Real work still required

The repository still does **not** prove that any of the following have happened merely because v0.25 tooling exists:

- four or more independently managed VPS validators are running,
- a real multi-operator genesis ceremony occurred,
- a real continuous 24h/72h/7-day campaign completed,
- all authorized fault/load/storage campaigns ran on independent hosts,
- backup/restore and clean-host state sync succeeded on real hosts,
- a protected remote signer/HSM-equivalent path was deployed and drilled,
- validator-governance activation was exercised on independently operated nodes,
- production-style public edge protections were deployed,
- an independent security review was commissioned or completed.

Those are external operational/review tasks. v0.25 only makes the resulting evidence harder to mix, silently alter or overstate.

## Security notes

- Never use validator consensus private keys as evidence-signing keys.
- Never commit evidence-signing private keys to Git.
- Evidence artifacts should not contain API tokens, seed phrases, validator private keys or TLS private keys.
- Fault campaigns must be performed only on systems you own or are explicitly authorized to test.
- A signed self-attestation is not the same as independent verification.
- A frozen review candidate is not a completed audit and not mainnet approval.
