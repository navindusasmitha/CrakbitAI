# Crakbit Chain v0.26 Alpha — Independent Review Remediation / Re-Freeze

**Package:** `0.26.0a1`  
**Consensus candidate:** CometBFT `v0.40.0`  
**Governed execution:** `crakbit-execution/3`  
**Status:** public-testnet / independent-review remediation tooling — **not production mainnet**.

Production CRKBIT has **not launched**. There is no official CRKBIT presale or production token contract. This software must not be used to custody real value.

## Purpose

v0.25 created a strict evidence boundary before a candidate can be frozen for independent review. v0.26 handles what happens **after reviewers return findings**: normalize findings with stable IDs, bind fixes to commits/config, require signed retests for high/critical issues against the exact candidate commit, record supply-chain and public-edge evidence, supersede stale candidates when identity/evidence changes, and sign a new re-freeze only when the modeled remediation gate passes.

A passing v0.26 gate is **not a mainnet approval**. It proves only that the supplied signed review/remediation evidence is internally consistent according to the v0.26 rules.

## What v0.26 adds

- package/CLI `0.26.0a1`,
- signed independent-review findings register,
- deterministic/stable finding IDs (`CRK-REV-...`),
- severity/component/title/affected-commit/reproduction metadata,
- remediation commit + optional config hash + mandatory regression-test binding for remediated findings,
- signed independent retest records,
- hard re-freeze blocker until every high/critical finding is declared remediated and the latest retest **passes against the exact candidate commit**,
- signed reproducible-build / supply-chain attestation hooks,
- dependency-lock + SBOM hash binding,
- signed public-edge TLS/WAF/DDoS/load/failover evidence format without provider secrets,
- requirement for two or more passing public-edge attestations,
- candidate supersession reasons when source/package/CometBFT/genesis/dependencies/review evidence changes,
- signed post-remediation review re-freeze,
- explicit claims that independent review is not globally complete and production mainnet is not ready,
- v0.26 regression tests.

## 1. Import review findings

Example `findings.json`:

```json
{
  "findings": [
    {
      "external_id": "AUD-001",
      "severity": "critical",
      "component": "consensus/application",
      "title": "Example review finding",
      "status": "remediated",
      "affected_commit": "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA",
      "reproduction": "Reviewer reproduction summary",
      "remediation_commit": "BBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB",
      "regression_test": "tests/test_example.py::test_regression"
    }
  ]
}
```

Build a signed register with a **review/evidence signing key**, not a validator consensus key:

```bash
crakchain review-findings-v26-build \
  --key private/reviewer-evidence-key.json \
  --review-id review-2026-001 \
  --reviewer "Independent Review Team" \
  --source-commit AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA \
  --input findings.json \
  --output runtime/review/findings-v26.json
```

Stable IDs are derived from the review ID, external finding ID, component and title. Silent changes to those identity fields therefore change the stable ID and signature.

## 2. Record independent retests

After fixes are assembled into the exact candidate commit being considered for re-freeze:

```bash
crakchain review-retest-v26-build \
  --key private/retest-evidence-key.json \
  --reviewer "Independent Retest Reviewer" \
  --finding-id CRK-REV-0123456789ABCDEF \
  --tested-commit EXACT_CANDIDATE_GIT_SHA \
  --result passed \
  --evidence report=runtime/review/retest-report.json \
  --output runtime/review/retest-AUD-001.json
```

For every high/critical finding, v0.26 checks the **latest signed retest for the exact candidate commit**. A passed retest on an older commit does not unlock the candidate. If the latest candidate retest fails, re-freeze is blocked.

## 3. Supply-chain / reproducible-build attestation

```bash
crakchain supply-attestation-v26-build \
  --key private/build-attestor-key.json \
  --attestor "Independent Build Verifier" \
  --source-commit EXACT_CANDIDATE_GIT_SHA \
  --package-version 0.26.0a1 \
  --dependency-lock-sha256 LOCKFILE_SHA256 \
  --sbom-sha256 SBOM_SHA256 \
  --python-reproducible \
  --go-reproducible \
  --dependency-review-complete \
  --transitive-sbom-complete \
  --output runtime/review/supply-attestation-v26.json
```

The format is an attestation hook. The repository does not independently prove that a build or supply-chain review happened merely because a signed JSON file exists.

## 4. Public-edge security / capacity attestations

At least two edge attestations are required by the v0.26 remediation gate:

```bash
crakchain edge-attestation-v26-build \
  --key private/edge-evidence-key.json \
  --operator edge-operator-a \
  --edge-id public-edge-a \
  --source-commit EXACT_CANDIDATE_GIT_SHA \
  --tls-min-version 1.2 \
  --tls-automation \
  --waf-enabled \
  --ddos-protection-enabled \
  --load-test-passed \
  --failover-drilled \
  --capacity-rps 500 \
  --sustained-minutes 60 \
  --output runtime/review/edge-a-v26.json
```

The record intentionally stores no API keys, provider tokens, certificate private keys or WAF secrets.

## 5. Build the hard remediation gate

```bash
crakchain remediation-gate-v26-build \
  --findings runtime/review/findings-v26.json \
  --retest runtime/review/retest-AUD-001.json \
  --supply-attestation runtime/review/supply-attestation-v26.json \
  --edge-attestation runtime/review/edge-a-v26.json \
  --edge-attestation runtime/review/edge-b-v26.json \
  --candidate-source-commit EXACT_CANDIDATE_GIT_SHA \
  --package-version 0.26.0a1 \
  --cometbft-version v0.40.0 \
  --application-genesis-sha256 APP_GENESIS_SHA256 \
  --consensus-genesis-sha256 COMET_GENESIS_SHA256 \
  --previous-freeze runtime/review/review-freeze-v25.json \
  --output runtime/review/remediation-gate-v26.json
```

The gate requires:

- every high/critical finding is declared remediated,
- every high/critical finding has a latest `passed` retest on the exact candidate commit,
- supply-chain/reproducible-build gate passes for the candidate source/package,
- at least two public edges pass TLS/WAF/DDoS/load/failover requirements,
- all public-edge attestations bind to the candidate source commit.

Low/medium findings remain visible in the register and can be handled according to the independent review/remediation policy, but v0.26 specifically hard-blocks unresolved or un-retested high/critical findings.

## 6. Supersession and signed re-freeze

When a previous freeze is supplied, v0.26 records why it is superseded. Source/package/CometBFT/genesis/dependency identity changes are explicit reasons; new review/remediation evidence also creates a new immutable candidate rather than mutating the old freeze in place.

After `refreeze_allowed=true`:

```bash
crakchain review-refreeze-v26-build \
  --key private/review-freeze-key.json \
  --remediation-gate runtime/review/remediation-gate-v26.json \
  --artifact findings=runtime/review/findings-v26.json \
  --artifact retest=runtime/review/retest-AUD-001.json \
  --artifact supply=runtime/review/supply-attestation-v26.json \
  --artifact edge-a=runtime/review/edge-a-v26.json \
  --artifact edge-b=runtime/review/edge-b-v26.json \
  --review-scope "consensus/application" \
  --review-scope "validator governance" \
  --review-scope "network/RPC" \
  --review-scope "cryptography/key custody" \
  --review-scope "browser wallet" \
  --output runtime/review/re-freeze-v26.json
```

The new signed freeze commits to the candidate source/package/CometBFT/genesis/dependency/SBOM identity, the exact remediation gate hash and each named artifact hash.

## Important boundary

v0.26 still does **not** claim:

- the public testnet has actually completed independent 7-day operation,
- every operator attestation is independently verified,
- the security review scope is complete,
- economic security has been independently approved,
- legal/regulatory review is complete,
- production mainnet is safe to launch.

Those external gates remain mandatory. v0.26 only prevents a reviewed candidate from being silently changed or re-frozen while high/critical remediation/retest and modeled release evidence are incomplete.
