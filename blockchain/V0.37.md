# Crakbit Chain v0.37 Alpha — Public-Testnet Execution and Review Hardening

**Package:** `0.37.0a1`
**Active testnet PoW:** `crakpow-scrypt-v1`
**Status:** public-testnet execution and review-preparation alpha
**Production mainnet:** not launched
**Production CRKBIT:** not launched

v0.37 adds signed, cross-bound evidence artifacts around the existing v0.35/v0.36 public-testnet workflow. It does not create independent infrastructure, replace external review, activate a new consensus algorithm, or authorize a production launch.

## Implemented in v0.37

- signed multi-host deployment plans with per-node operator runbooks,
- minimum node, operator, provider, region, network-group and miner-operator gates,
- rejection of secret-like fields and credential-bearing RPC URLs,
- signed pool payout policy evidence with hot/cold wallet separation,
- payout caps, manual holds, confirmation depth and multi-operator approval requirements,
- benchmark/algorithm-decision binding checks,
- optional RandomX testnet-proposal binding without automatic activation,
- signed public-testnet independent-review candidate bundle,
- explicit source/package/chain/genesis and v0.36 handoff linkage,
- semantic verification of derived deployment and payout checks,
- CLI build/verify commands and regression coverage.

## Evidence chain

| Artifact | Inputs | What it proves | What it does not prove |
| --- | --- | --- | --- |
| Deployment plan | v0.37 source, package, chain/genesis, node metadata | Signed intended topology meets declared diversity gates | Hosts exist, are independent, or are securely configured |
| Payout policy | Hot/cold addresses, limits, approvals, confirmations | Signed operational policy has conservative controls | Private-key security or that operators follow the policy |
| Algorithm review gate | Real benchmark gate, human decision, v0.36 handoff, optional proposal | Supplied records are signed and cross-bound; required review assertions were made | Reviewer independence or safe consensus activation |
| Review bundle | All artifacts above plus v0.36 handoff | Candidate package is internally consistent and ready to hand to reviewers | Review completion, mainnet readiness, or launch authorization |

The review assertions are deliberately recorded as assertions, not cryptographic proof that a reviewer is independent.

## 1. Prepare public node metadata

Create `evidence/nodes-v37.json` without passwords, tokens, seeds, private keys or credential-bearing URLs:

```json
{
  "nodes": [
    {
      "node_id": "node-a",
      "operator_id": "operator-a",
      "provider": "provider-a",
      "region": "region-a",
      "network_group": "network-a",
      "roles": ["node", "miner"],
      "rpc_url": "https://node-a.example",
      "p2p_endpoint": "node-a.example:28444"
    }
  ]
}
```

A passing plan requires at least four unique nodes/operators, two providers, two regions, two network groups and two miner/pool operators. Add at least four real entries; the one-entry JSON above is only the field shape.

Build the signed plan:

```powershell
crakchain pow-deployment-v37-build `
  --key private\release-evidence.json `
  --source-commit <exact-40-character-v0.37-sha> `
  --chain-id crakbit-pow-testnet-v1 `
  --genesis-hash <64-hex-genesis> `
  --nodes evidence\nodes-v37.json `
  --output evidence\deployment-v37.json
```

The generated runbooks reference the existing v0.36 node and campaign commands. The command creates evidence only; it never connects to or mutates the declared hosts.

## 2. Build the payout policy

```powershell
crakchain pow-payout-policy-v37-build `
  --key private\release-evidence.json `
  --hot-wallet-address <crk1-hot-watch-address> `
  --cold-wallet-address <crk1-cold-watch-address> `
  --maximum-single-payout-atomic 100000000 `
  --maximum-batch-payout-atomic 500000000 `
  --daily-payout-limit-atomic 1000000000 `
  --manual-hold-above-atomic 50000000 `
  --approvals-required 2 `
  --minimum-confirmations 6 `
  --output evidence\payout-policy-v37.json
```

Only public addresses belong in this artifact. Never put a private key, seed phrase or wallet password in evidence JSON.

## 3. Build the algorithm-review gate

```powershell
crakchain pow-algorithm-review-v37-build `
  --key private\release-evidence.json `
  --benchmark-gate evidence\benchmark-gate-v34.json `
  --algorithm-decision evidence\algorithm-decision-v34.json `
  --v36-handoff evidence\review-handoff-v36.json `
  --external-benchmark-review-asserted `
  --external-consensus-review-asserted `
  --output evidence\algorithm-review-v37.json
```

If the human decision is `randomx`, `--activation-proposal` is required. The proposal remains testnet-only and records `consensus_activated=false`. If the decision is `scrypt`, no activation proposal is required because the current testnet algorithm remains unchanged.

## 4. Build the review candidate bundle

```powershell
crakchain pow-review-bundle-v37-build `
  --key private\release-evidence.json `
  --source-commit <exact-40-character-v0.37-sha> `
  --deployment-plan evidence\deployment-v37.json `
  --payout-policy evidence\payout-policy-v37.json `
  --algorithm-review-gate evidence\algorithm-review-v37.json `
  --v36-handoff evidence\review-handoff-v36.json `
  --output evidence\public-testnet-review-bundle-v37.json
```

The v0.36 handoff is expected to reference its own older source commit. v0.37 records that commit as `supersedes_v36_source_commit` and binds the new bundle to the v0.37 deployment commit; it does not incorrectly require both versions to share one Git SHA.

## Verification

Each artifact has a corresponding `*-verify` command. Verification checks signatures, content-derived IDs, prohibited production claims and available semantic/cross-artifact constraints.

```powershell
crakchain pow-review-bundle-v37-verify `
  --record evidence\public-testnet-review-bundle-v37.json
```
